# مواصفة بنك أسئلة استكشاف الميول — الإصدار 1.3

> هذه وثيقة الإصدار الجديد. تبقى مواصفة v1.2 محفوظة في `question_bank_specification.md` للحفاظ على تاريخ النتائج السابقة.

**المشروع:** منصة مسارك للتوجيه الأكاديمي والمهني لطلاب المرحلة الثانوية في اليمن  
**الجمهور:** فريق التحليل والمحتوى والتطوير والاختبار  
**الحالة:** معتمدة تصميميًا للنسخة الحالية  
**الإصدار:** 1.3  
**عدد المواقف:** 18 موقفًا  
**عدد الخيارات السلوكية:** 4 خيارات RIASEC في كل موقف  
**خيار إضافي في الواجهة:** «لا يشبهني أي من هذه التصرفات»

---

## 1. الغرض

توثق هذه الوثيقة:

- نصوص مواقف التقييم.
- الخيارات السلوكية المرتبطة بمجالات RIASEC.
- طريقة استجابة الطالب.
- الاختيار الأساسي في كل موقف.
- التقييم الاختياري لكل خيار سلوكي.
- حالات عدم التمثيل وعدم القدرة على الحكم.
- قواعد التسجيل.
- نموذج الحساب الأولي.
- ضوابط تفسير النتيجة.

الأداة استكشافية وليست اختبار قدرات أو تشخيص شخصية، ولا تنتج تخصصًا صحيحًا وحيدًا، ولا تمثل درجاتها نسبة نجاح أو ضمان ملاءمة.

# 4. نموذج الاستجابة المعتمد

## 4.1 الاختيار الأساسي

في كل موقف تظهر أربعة تصرفات تمثل أربعة مجالات مختلفة من RIASEC.

يختار الطالب **اختيارًا أساسيًا واحدًا فقط** يمثل التصرف الأقرب إليه.

مثال:

```text
○ التصرف الأول
○ التصرف الثاني
○ التصرف الثالث
○ التصرف الرابع
○ لا يشبهني أي من هذه التصرفات
```

الاختيار الأساسي هو الإشارة الرئيسية المستخدمة في حساب الميل.

---

## 4.2 الخيار الخامس

يظهر في كل موقف خيار خامس ثابت:

> **لا يشبهني أي من هذه التصرفات**

هذا الخيار:

- لا ينتمي إلى أي مجال من RIASEC.
- ليس له وزن RIASEC.
- لا يخزن كـ`question_option`.
- يمثل أن الطالب فهم الموقف ولكن الخيارات الأربعة لا تمثله بصورة مناسبة.
- يسجل داخليًا كحالة استجابة مستقلة.

في نموذج البيانات الحالي:

```text
response_type = none
primary_option_id = NULL
```

---

## 4.3 عدم القدرة على الحكم

يوجد كذلك اختيار منفصل:

> **لا أستطيع الحكم على هذا الموقف**

ويختلف عن الخيار الخامس.

### الفرق

**لا يشبهني أي من هذه التصرفات**

يعني:

> فهمت الموقف، لكن لا أرى نفسي في أي من التصرفات الأربعة.

أما:

**لا أستطيع الحكم على هذا الموقف**

فيعني:

> لا أملك خبرة أو فهمًا كافيًا لأعطي إجابة موثوقة.

ويسجل داخليًا:

```text
response_type = cannot_judge
primary_option_id = NULL
```

ولا يدخل هذا الموقف في حساب درجات RIASEC.

# 5. التقييم الاختياري لكل خيار

بعد اختيار أحد الخيارات الأربعة كاختيار أساسي، يمكن للطالب — بشكل **اختياري** — تقييم أي عدد من الخيارات الأربعة.

لا يشترط تقييم كل الخيارات.

السلم المعتمد:

| استجابة الطالب | القيمة |
|---|---:|
| يشبهني جدًا | +2 |
| يشبهني | +1 |
| محايد / غير متأكد | 0 |
| لا يشبهني | -1 |
| لا يشبهني إطلاقًا | -2 |

يمكن للطالب تقييم:

```text
0 خيارات
1 خيار
2 خيارين
3 خيارات
أو جميع الخيارات الأربعة
```

التقييمات الثانوية لا تستبدل الاختيار الأساسي.

---

# 6. الفرق بين عدم التقييم والقيمة صفر

هذه قاعدة ملزمة.

إذا لم يقيم الطالب خيارًا:

```text
NULL
```

ولا يعامل على أنه:

```text
0
```

لأن:

```text
NULL = لم يقدم تقييمًا
0    = قدم تقييمًا صريحًا بأنه محايد أو غير متأكد
```

ويجب الحفاظ على هذا الفرق في قاعدة البيانات والحساب.

---

# 7. العلاقة بين الاختيار الأساسي والتقييم الاختياري

مثال:

اختار الطالب:

```text
أبحث عن سبب المشكلة
```

كاختيار أساسي.

يمكن بعد ذلك أن يقيم الخيارات مثلًا:

```text
R = -1
I = +2
A = NULL
C = +1
```

في هذه الحالة:

- المجال `I` حصل على إشارة Primary.
- `I` حصل أيضًا على تقييم `+2`.
- `R` حصل على تقييم `-1`.
- `C` حصل على تقييم `+1`.
- `A` لم يقيم، لذلك يبقى `NULL`.

---

# 8. الاتساق بين الاختيار الأساسي والتقييم

قد يختار الطالب خيارًا كاختيار أساسي ثم يعطي الخيار نفسه تقييمًا سلبيًا مثل:

```text
-1
```

أو:

```text
-2
```

هذه حالة غير معتادة لكنها لا تعدل تلقائيًا.

يمكن للواجهة إظهار رسالة تأكيد مثل:

> اخترت هذا التصرف بوصفه الأقرب إليك، لكنك قيمته بأنه لا يشبهك. هل تريد الاحتفاظ بهذه الإجابة؟

إذا أكد الطالب:

- تحفظ الإجابة كما هي.
- لا يغير النظام التقييم تلقائيًا.
- يمكن استخدام هذا النوع من الحالات لاحقًا في فحص جودة البيانات.

لا يلزم إضافة حقل دائم في قاعدة البيانات لهذه الحالة ما لم تظهر حاجة فعلية مستقبلًا.

# 9. قواعد الخيار الخامس وعدم القدرة على الحكم

في الإصدار 1.3:

### إذا اختار الطالب:

```text

```

فإن:

```text
primary_option_id = NULL

```

ولا تعرض تقييمات الخيارات الأربعة لذلك الموقف.

### وإذا اختار:

```text

```

فإن:

```text
primary_option_id = NULL
response_type = cannot_judge
```

ولا تعرض تقييمات الخيارات.

هذا يمنع تسجيل إشارتين متعارضتين لنفس الموقف.

# 11. قواعد واجهة الطالب

لا يظهر للطالب:

- `R`
- `I`
- `A`
- `S`
- `E`
- `C`
- القيم الرقمية.
- المعادلات.
- الأوزان الداخلية.
- اسم المجال المرتبط بالخيار.

يرى الطالب فقط:

1. نص الموقف.
2. التصرفات الأربعة.
3. الخيار الخامس.
4. خيار عدم القدرة على الحكم.
5. التقييمات النصية الاختيارية عند الحاجة.

# 16. المكون الأساسي Primary Component

لكل مجال `d`:

```text
N_d
```

= عدد المواقف الصالحة التي ظهر فيها المجال `d`.

و:

```text
K_d
```

= عدد المرات التي اختار فيها الطالب مجال `d` كاختيار أساسي.

ثم:

```text
P_d = K_d / N_d
```

حيث:

```text
0 ≤ P_d ≤ 1
```

مثال:

إذا ظهر المجال `I` في 10 مواقف صالحة واختير أساسيًا في 4:

```text
P_I = 4 / 10 = 0.40
```

---

# 17. المكون الثانوي للتقييمات

لكل مجال `d`:

```text
M_d
```

= عدد التقييمات الاختيارية الفعلية التي قدمها الطالب لذلك المجال.

والقيم الممكنة:

```text
-2, -1, 0, +1, +2
```

يعرف مجموعها:

```text
Σr_d
```

---

## 17.1 Shrinkage

لتقليل تأثير عدد قليل جدًا من التقييمات يستخدم معامل أولي:

```text
λ = 2
```

ويحسب:

```text
Rraw_d = Σr_d / (M_d + λ)
```

ويمكن فهم `λ = 2` كإضافة تقييمين محايدين افتراضيين.

إذا لم توجد تقييمات:

```text
M_d = 0
Σr_d = 0
Rraw_d = 0
```

---

## 17.2 تحويل التقييم إلى مجال 0–1

لأن:

```text
-2 ≤ Rraw_d ≤ +2
```

يحول إلى:

```text
R_d = (Rraw_d + 2) / 4
```

فتصبح:

```text
0 ≤ R_d ≤ 1
```

---

# 18. تغطية التقييمات الاختيارية

يحسب:

```text
C_d = M_d / N_d
```

وهو مقدار التغطية الفعلية للتقييمات.

إذا قيم الطالب كل مرات ظهور المجال:

```text
C_d = 1
```

وإذا لم يقيم شيئًا:

```text
C_d = 0
```

---

# 19. الوزن المتكيف للتقييمات

التقييمات الثانوية لا تأخذ 30% دائمًا.

بل:

```text
W_d = 0.30 × C_d
```

إذن:

```text
0 ≤ W_d ≤ 0.30
```

إذا لم توجد تقييمات:

```text
W_d = 0
```

إذا اكتملت التقييمات:

```text
W_d = 0.30
```

---

# 20. الدرجة النهائية لكل مجال

تحسب الدرجة:

```text
Score_d =
100 × ((1 - W_d) × P_d + W_d × R_d)
```

وبالتالي:

```text
0 ≤ Score_d ≤ 100
```

---

## 20.1 عندما لا توجد تقييمات اختيارية

إذا:

```text
C_d = 0
```

إذن:

```text
W_d = 0
```

فتصبح:

```text
Score_d = 100 × P_d
```

أي أن النظام يعتمد كليًا على الاختيارات الأساسية.

---

## 20.2 عند التغطية الكاملة

إذا:

```text
C_d = 1
```

إذن:

```text
W_d = 0.30
```

فتصبح:

```text
Score_d =
100 × (0.70 × P_d + 0.30 × R_d)
```

أي:

```text
70% Primary
30% Ratings
```

---

# 21. مثال حساب مبسط

افترض أن مجال `I` ظهر في:

```text
N_I = 10
```

واختاره الطالب أساسيًا:

```text
K_I = 4
```

إذن:

```text
P_I = 4 / 10 = 0.40
```

قدم الطالب 5 تقييمات للمجال، وكان مجموعها:

```text
Σr_I = 6
```

إذن:

```text
M_I = 5
λ = 2

Rraw_I = 6 / (5 + 2)
       = 0.8571
```

ثم:

```text
R_I = (0.8571 + 2) / 4
    ≈ 0.7143
```

التغطية:

```text
C_I = 5 / 10
    = 0.50
```

وزن التقييم:

```text
W_I = 0.30 × 0.50
    = 0.15
```

الدرجة النهائية:

```text
Score_I =
100 × ((1 - 0.15) × 0.40 + 0.15 × 0.7143)

≈ 44.7
```

# 28. ملاحظة منهجية حول المعادلة

المعادلة الحالية هي **نموذج هندسي أولي للنسخة 1.2**.

المعاملات:

```text
λ = 2
حد أقصى للتقييمات الثانوية = 30%
```

ليست معاملات مثبتة سيكومتريًا حتى الآن.

يجب اختبارها على بيانات حقيقية قبل اعتبارها ثابتة علميًا.

كذلك يوجد اختلاف بنيوي بين:

```text
P_d
```

الذي يعتمد على اختيار واحد من أربعة خيارات، وبين:

```text
R_d
```

الذي يحول تقييمًا ثنائي القطب من `-2` إلى `+2` إلى المجال `0..1`.

لذلك يجب التعامل مع الدمج الحالي بوصفه **صيغة تشغيلية أولية قابلة للمعايرة** وليس حقيقة سيكومترية نهائية.

- الصفر يعني تقييمًا محايدًا صريحًا.
- لا تدخل سرعة الإجابة في الدرجة.

- تحسب المجالات الستة بصورة مستقلة.

- لا تدمج التحصيل أو الثقة أو رأي الأسرة داخل درجة الميل.

- تعرض عدة تخصصات للاستكشاف.

# 32. الرموز البصرية الاختيارية

يمكن استخدام Emoji أو رمز بصري بجانب النص لتحسين الاستخدام على الهاتف.

مثال:

```text
😄 يشبهني جدًا
🙂 يشبهني
😐 محايد / غير متأكد
🙁 لا يشبهني
☹️ لا يشبهني إطلاقًا
```

لكن:

- النص العربي يبقى ظاهرًا.
- Emoji عنصر واجهة فقط.
- لا يخزن في قاعدة البيانات.
- لا يؤثر على الحساب.
- يجب مراجعته مع عينة من الطلاب اليمنيين قبل اعتماده النهائي.

# 33. تدقيق الجودة

يجب أن تغطي الاختبارات لاحقًا:

- أربعة خيارات RIASEC فقط لكل سؤال.
- عدم وجود مجال خامس للخيار `none`.
- صحة `primary_option_id`.
- صحة `response_type`.
- عدم وجود Primary مع `none`.
- عدم وجود Primary مع `cannot_judge`.
- قبول القيم `-2..+2` فقط.
- الفرق بين `NULL` و`0`.
- إمكانية وجود صفر تقييمات.
- إمكانية وجود عدة تقييمات.
- منع تكرار تقييم نفس الخيار في الإجابة نفسها.
- استبعاد `cannot_judge` من الحساب.
- احتساب `none` ضمن المواقف المعالجة دون منح Primary.
- صحة التوزيع المتوازن للمجالات.
- سلامة الحسابات الستة.
- عدم كشف رموز المجالات أو الحساب للواجهة.

# 35. قرار الاعتماد الحالي

## المعتمد تصميميًا

- 18 موقفًا.
- 4 خيارات RIASEC لكل موقف.
- 72 خيارًا سلوكيًا إجمالًا.
- 12 ظهورًا لكل مجال.
- اختيار أساسي واحد.
- خيار خامس مستقل:
  `لا يشبهني أي من هذه التصرفات`.
- حالة مستقلة:
  `لا أستطيع الحكم على هذا الموقف`.
- تقييم اختياري بقيم `-2..+2`.
- `NULL` مختلف عن `0`.
- ست درجات مستقلة لـRIASEC.
- نموذج حساب أولي يجمع Primary والتقييمات الثانوية بصورة متكيفة.
- حفظ إصدار طريقة الحساب في `scoring_version`.

## غير المعتمد سيكومتريًا بعد

لا تعد القيم التالية حقائق علمية نهائية:

```text
λ = 2
30% maximum rating weight
15/18 minimum valid situations
```

بل هي قرارات تشغيلية أولية تحتاج اختبارًا ومعايرة.

# 36. النتيجة التي يراها الطالب

تعرض:

1. المجالات الستة ودرجاتها.
2. أعلى المجالات بصورة وصفية.
3. توضيح التقارب أو التعادل إن وجد.
4. تخصصات متعددة للاستكشاف.
5. توضيح أن النتائج تعكس ميولًا حالية وليست حكمًا نهائيًا.
6. مؤشر جودة/اكتمال الأدلة عند الحاجة.

ولا تعرض:

- «أنت من النوع X فقط».
- «هذا التخصص مناسب لك بنسبة 90%».
- «ستنجح بالتأكيد».
- «هذا هو أفضل تخصص لك».
