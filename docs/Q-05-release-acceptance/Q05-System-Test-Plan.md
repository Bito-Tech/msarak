## 3. منهجية الاختبار (طبقتان متكاملتان)

### الطبقة الأولى — آلية (Automated Regression)

تشغيل `php artisan test` بالكامل كخط أساس، ثم إعادة التشغيل بعد كل إصلاح. تغطي هذه الطبقة:

- الرحلات الكاملة عبر HTTP (`CompleteJourneyIntegrationTest`، `AssessmentJourney/*`).
- المنطق والأمان (`ResultOwnershipSecurityTest`، `H04ProfileResultSecurityTest`،
  `AuthenticationAuthorizationRegressionTest`).
- الإدارة (`Admin/AssessmentVersionManagementTest`، `Admin/StatisticsTest`).
- قاعدة البيانات والعقود (`Database/*`، `ResultContractVerificationTest`).

**خط الأساس المعتمد (2026-09-26):**

```text
Tests: 444 | Assertions: 2799 | Failures: 0 | Errors: 0
PHPUnit Deprecations: 6 (غير معيقة — إشعارات ترقية فقط)
```

### الطبقة الثانية — يدوية بشرية حقيقية (Manual / GUI)

تنفَّذ عبر متصفح حقيقي على الخادم المحلي `http://127.0.0.1:8000` وتغطّي ما لا يستطيع
الاختبار الآلي التحقق منه: التجربة الحسية، RTL، التجاوب، حالات الحافة التي تتدخل فيها
الذاكرة البشرية، والأمان بالتنقل الفعلي بين الحسابات.

> **قياس واقعي:** واجهات الإدارة (F-05) **غير مدمجة في هذا الفرع** — مسارات الإدارة
> موجودة كـ API فقط. لذلك تُختبر رحلة الإدارة على مستوى HTTP (مغطاة آلياً)، ويُسجَّل
> التحقق البصري للوحة الإدارة كـ **Pending F-05 merge** في `Q05-Final-Release-Evidence.md`.

## 5. قواعد الأدلة (Evidence Rules)

كل سيناريو يُسجَّل وفق قالب `release-readiness.md` §6:

```text
ID:
Area:
Scenario / Check:
Preconditions:
Steps:
Expected:
Actual:
Result: PASS / FAIL
Commit SHA:
Evidence:
Linked Issue:
Retest:
Notes:
```

- الدليل مرتبط بحالة فعلية، قابل للتحقق، وموثَّق بـ Commit SHA.
- لا يُسمح بتأجيل Critical. و High يحتاج قراراً صريحاً مبرراً من Release Gate.

## 6. معايير القبول (Issue #42)

- جميع الاختبارات الآلية ناجحة.
- الرحلات الأساسية مجربة.
- العيوب مصنفة.
- لا توجد مشكلة حرجة مفتوحة.
- التقرير يحدد القرار بوضوح.
